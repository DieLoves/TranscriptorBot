# Handoff

Дата: 2026-10-09. Проект: `/home/dev/workspace/projects/transcriptbot`.

## Objective

Реализовать Telegram-бота транскрипции через Groq по спецификации v1.
После каждого этапа выполнить соответствующие и полные доступные проверки,
создать коммиты и остановиться до указаний пользователя.
Пользователь разрешил push изменений по завершении этапа 5.
Рабочее развёртывание требует отдельного согласования.

## Current state

- **Этапы 1–5 завершены.** Полный финальный прогон: 340 passed.
  Этап 6 не начат. Worker выполняет `download → prepare → transcribe → assemble
  → deliver`; существующий Telegram sender подтверждает preview/TXT/JSON
  отдельно и отмечает завершение с `cleanup_pending`.
- Медиа: FFmpeg потоково считает декодированные отсчёты первой аудиодорожки
  16 кГц и находит паузы; полного промежуточного WAV нет. Границы хранятся
  в целых отсчётах, целевая часть 600 с, поиск паузы в последних 8 с от 0,3 с.
  Хвост меньше 10 мс присоединяется к предыдущей части для минимальной длины Groq.
- Только текущий `current.wav`: PCM16/16 кГц/моно, размер и число отсчётов
  проверяются до API. Для точности извлечение декодирует источник от начала
  и использует `atrim` после ресэмплинга. Это требует повторного чтения
  исходника для каждой части; таймаут операции остаётся 300 с.
- FFmpeg/FFprobe допускают только file и закрытый набор демультиплексоров.
  HLS/concat/сеть запрещены, внешние дорожки MOV отключены defaults и проверены
  изменёнными контейнерами. Таймаут/отмена останавливают всю группу потомков;
  ключи дочерним процессам не передаются.
- `AsyncGroq(max_retries=0)` запрашивает verbose_json/segment с автоязыком,
  без слов и дополнительного prompt. Streaming raw response ограничен
  по размеру и сохраняет исходный объект, включая неизвестные поля.
- `chunks.json` и `response-NNNN.json` публикуются неизменно с fsync.
  Ответы привязаны к исходному SHA-256, ID, модели, номеру и границам части.
  SQLite хранит путь и хеш; опубликованный ответ без подтверждения SQLite
  восстанавливается без API. Повреждённые/изменившиеся ответы не распознаются заново.
- Для одной части JSON — исходный объект Groq; для нескольких — полный текст,
  фактическая длительность, язык первой части, глобальные сегменты с новыми ID,
  границы и исходные локальные ответы в chunks. TXT/JSON публикуются атомарно.
  `deliver` восстанавливается по готовым файлам без исходника и повторного Groq.
- Миграция 003 добавляет `groq_usage`: резервирование перед запросом,
  консервативный расход успехов/неопределённых исходов, освобождение после отказа.
  Настройки 7200 с/час и 28800 с/сутки изменяемые. 429 использует Retry-After,
  без него — 60/120/240/.../3600 с; обычные ошибки — 5/15/45/135/300 с.
  Сроки/счётчики переживают рестарт, ожидание держит FIFO. Счётчики сбрасываются
  атомарно с ответом части. Отмена/revision исключают позднюю доставку.
- Сохранены защищённые загрузчики этапа 4: HTTPX/HTTPcore проверяет весь DNS,
  соединяется с числовым публичным IP, сохраняет Host/SNI/TLS, отключает прокси,
  проверяет каждый redirect/размер/таймаут. Mail.ru допускает только HTTPS,
  cloud.mail.ru, datacloudmail.ru и их поддомены (домен подтверждён пользователем).
- yt-dlp: один защищённый RequestHandler, встроенный HttpFD, отдельная HTTP(S)
  аудиодорожка, локальные EJS/Deno, без внешних загрузчиков/удалённых компонентов.
  Плейлисты/эфиры/авторизация запрещены; лимит байтов суммарный для range.
- Telegram getFile — при наступлении очереди, кеш без обязательной второй копии;
  готовый source.json не требует повторного getFile. Источник сверяется SHA-256.
  assets/job_assets учитывают источники, кеш, WAV, части, результаты и .part.
- Telegram inbox/очередь/outbox/offset атомарны; durable polling/routers,
  владелец/группа/тема, статусы не чаще 5 с, раздельная восстановимая доставка.
  generation защищает от старых кнопок. SQLite/WAL/FULL, foreign keys,
  busy timeout 10 с, выделенный поток; один worker благодаря flock.
- Рабочие сервисы не запущены. .env не изменён, права 0600, исключён из Git.
  Не читать/не выводить значения ключей, не запрашивать их повторно.
  Приложение выполнило только один живой Groq-запрос на синтетической речи;
  рабочие Telegram/Bot API не вызывались. За пределы этапа 5 не переходить.
