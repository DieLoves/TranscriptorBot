# Handoff

Дата: 2026-10-08. Проект: `/home/dev/workspace/projects/transcriptbot`.

## Objective

Реализовать Telegram-бота транскрипции через Groq по согласованной спецификации v1.
После каждого этапа выполнить соответствующие и полные доступные проверки,
создать локальный коммит и остановиться до дальнейших указаний пользователя.
Push и развёртывание требуют отдельного согласования.

## Current state

- **Этапы 1 и 2 завершены**. Спецификация не изменена; этап 3 не начат.
- Есть конфигурация, CLI `transcriptbot bot`, `worker`, `migrate`, флаг `--check`,
  uv.lock, Docker/Compose с тремя сервисами, проверка окружения и SIGTERM/SIGINT.
- Реализован SQLite/WAL: отдельный поток и соединение в каждом процессе,
  foreign keys, busy timeout 10 секунд, `synchronous=FULL`, защищённые файлы.
- Версионированные SQL-миграции с SHA-256 применяются отдельной командой;
  сервисы отказываются запускаться без актуальной схемы. Миграция атомарна,
  её повторное и конкурентное применение проверено.
- Приём задания, лимиты пользователя/общей очереди, номер FIFO и регистрация
  Telegram update выполняются одной транзакцией `BEGIN IMMEDIATE`.
  Отказы также запоминаются; повтор update возвращает первоначальный результат.
- Есть условные переходы этапов, ожидания с сохранёнными сроками и счётчиками,
  отмена, окончательная ошибка, продолжение и завершение после доставки обоих файлов.
  Ожидание текущего задания блокирует последующие. Ошибка освобождает очередь;
  продолжение сохраняет ID, этап и части, но присваивает новый номер FIFO.
- Worker удерживает файловую блокировку на томе базы. При запуске читает
  сохранённое активное задание; репозиторий возвращает его раньше новых.
- `revision` защищает от поздних результатов после отмены/изменения состояния.
  `generation` и сохранённые результаты callback защищают новую попытку от старых кнопок.
- История ограничена владельцем и при групповом доступе — исходным чатом.
  Схема содержит `jobs`, `chunks`, `assets`/`job_assets`, `outbox`,
  `processed_updates`, `polling_state`, `queue_sequence`, `schema_migrations`.
  В SQLite нет текста расшифровки и тел ответов Groq — только ссылки на файлы.
- `bot` и `worker` пока открывают базу и ждут остановки. Polling, sender,
  скачивание, медиа-конвейер и физическая очистка файлов ещё не подключены.
- Рабочие сервисы не запущены; используются только автономные временные проверки.
  `.env` не изменялся, права 0600, исключён из Git. Ключи повторно не запрашивать.

## Key decisions and relevant files

- Спецификация: `docs/specs/transcriptbot-v1.md`; актуальный план:
  `docs/plans/transcriptbot-v1-implementation.md`.
- `src/transcriptbot/storage/database.py` и `migrations/001_initial.sql` —
  миграции и выделенный поток; `repository.py`, `models.py` — очередь и метаданные;
  `worker_lock.py` — блокировка на общем томе базы.
- Состояние задания и этап конвейера разделены. Частичный UNIQUE-индекс
  разрешает только одно активное/ожидающее задание.
- `transcriptbot migrate` не требует media-tools и каталога Telegram-кеша.
  Для контейнеров: `docker compose run --rm --no-deps worker migrate` перед сервисами.
  `--check` по-прежнему не создаёт базу и не вызывает API.
- Таблица `polling_state` пока только создана. Продвижение offset, регистрация
  ответов в outbox, sender и отметки Telegram реализовать в этапе 3;
  физическую очистку и reconciliation — в этапе 6.
- Репозиторий хранит обычные и quota-попытки отдельно. Политику повторов,
  обработку Retry-After и Groq-конвейер подключить в этапе 5.
- Python 3.12; aiogram 3; Groq `whisper-large-v3-turbo`; один worker;
  Redis/HTTP API нет. Результат и checkpoint остаются в рабочих файлах.
- Модель фиксирована, разбиение по паузам без перекрытия; успешные части
  не распознаются повторно. Продолжение доставки не возвращает к распознаванию.
- В группах проверять инициатора; результат выдавать в тот же чат/тему.
  В личке приём автоматический. Cleanup включает учтённый кеш Bot API;
  после ошибки файлы доступны 7 дней, история без содержимого — бессрочно.
- Зафиксированные образы/зависимости и официальный Bot API из этапа 1 сохранены.
  Bot API commit `e3e9dd8e5b3d7ab8537cd5a10dc31d5ffa8f82d1`, TDLib
  `bc9c263e2bfee06aaab41e82db51a103376030bc`; JavaScript solver yt-dlp локальный,
  загрузку скриптов во время работы не включать.
- `/home/dev/workspace/projects/groq_transcript/transcribe.py` и тесты —
  источник алгоритмов этапа 5, не готовый backend; соседний проект не изменять.
