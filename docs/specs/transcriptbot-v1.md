# Спецификация TranscriptBot v1

## 1. Назначение и техническая основа

Бот преобразует аудио и звуковую дорожку видео в текст через Groq, используя **`whisper-large-v3-turbo`**. Пользователь получает превью, полный текст файлом `.txt` и подробный результат `.verbose.json`.

Согласованные условия:

- Закрытый доступ по списку Telegram ID; ориентир — до 10 пользователей.
- Работа в личных чатах и группах.
- Один общий аккаунт Groq Free.
- Максимум одной записи: **2 ГБ и 4 часа**.
- Задания выполняются последовательно, в порядке поступления. Ожидание квоты текущим заданием задерживает следующие.
- Язык записи определяется автоматически; интерфейс бота — русский.

Стек:

| Назначение | Решение |
|---|---|
| Язык | Python 3.12 |
| Telegram | aiogram 3, long polling |
| Крупные вложения | Собственный официальный Telegram Bot API в режиме `--local` |
| Распознавание | Groq Python SDK |
| Анализ и подготовка медиа | FFmpeg, FFprobe |
| YouTube | yt-dlp с необходимыми зависимостями для JavaScript |
| Облако Mail.ru и прямые ссылки | HTTPX, собственные загрузчики |
| Очередь и история | SQLite |
| Развёртывание | Linux, Docker Compose |
| Проверки | pytest, Ruff |

Compose запускает три сервиса: бот, один обработчик заданий и Telegram Bot API. Бот принимает запросы независимо от длительной обработки. SQLite и рабочие файлы находятся на постоянных локальных томах; база использует WAL. Отдельные Redis и веб-сервер не требуются.

Для полной поддержки YouTube yt-dlp требует внешнюю среду JavaScript; в образ обработчика включается Deno. [Документация yt-dlp](https://github.com/yt-dlp/yt-dlp/wiki/EJS).

## 2. Источники и взаимодействие с пользователем

### Поддерживаемые источники

- Вложения Telegram: аудио, видео, документы с медиафайлом, голосовые сообщения, видеокружки.
- Публичные отдельные видео YouTube, включая короткие ссылки и Shorts.
- Публичные ссылки Облака Mail.ru на отдельный файл, включая файл внутри вложенных папок.
- Прямые HTTP/HTTPS-ссылки на аудио или видео.

Для YouTube скачивается аудиодорожка. Ограничение размера относится к фактически скачиваемому файлу.

Поддерживаются распространённые форматы, включая MP3, WAV, M4A, OGG, Opus, FLAC, AAC, MP4, MKV, MOV и WebM. Пригодность определяется наличием декодируемой аудиодорожки через FFprobe, а не только расширением файла. При нескольких дорожках используется первая аудиодорожка.

В первую версию не входят пакетная обработка папок и плейлистов, прямые эфиры, источники с авторизацией, перевод, саммари, субтитры и разделение речи по говорящим.

### Запуск

**В личном чате:**

- Пользователь отправляет файл или одну ссылку.
- Бот автоматически создаёт задание.
- Также поддерживается `/transcribe <link>`.

**В группе:**

- `/transcribe` ответом на вложение или сообщение с одной ссылкой.
- `/transcribe <link>` отдельным сообщением.
- Поддерживается форма команды с именем бота: `/transcribe@BotName <link>`.
- Обычные сообщения и вложения автоматически не обрабатываются.
- Превью и файлы отправляются в ту же группу, с сохранением темы обсуждения, если она используется.

Проверяется Telegram ID **инициатора команды**. Разрешённый пользователь может пользоваться ботом в любой группе, куда бот добавлен. Запросы от анонимных администраторов и каналов отклоняются, поскольку пользовательский ID недоступен.

### Команды и кнопки

| Интерфейс | Поведение |
|---|---|
| `/start`, `/help` | Правила использования, источники и ограничения |
| `/transcribe <link>` | Создать задание по ссылке |
| `/transcribe` ответом | Создать задание по исходному сообщению |
| `/jobs` | Последние 10 собственных заданий |
| `/status <id>` | Статус собственного задания |
| «Отменить» | Остановить собственное незавершённое задание |
| «Продолжить» | Повторить задание после окончательной ошибки |

В группах история и статусы доступны только для собственных заданий из этой группы. В личном чате пользователь видит все свои задания. Управление чужими заданиями запрещено.

Бот сообщает ID задания, место в очереди и текущий этап: скачивание, подготовка аудио, распознавание части `N/M`, ожидание квоты, отправка результата. Статус обновляется в одном сообщении.

## 3. Обработка аудио и формат результата

Конвейер:

1. Проверить доступ и корректность запроса.
2. Сохранить задание в SQLite.
3. При наступлении очереди скачать источник.
4. Определить размер, длительность и аудиодорожку.
5. Подготовить фрагменты и последовательно отправить их в Groq.
6. Собрать результат.
7. Отправить превью, TXT и JSON.
8. Удалить содержательные файлы после подтверждённой отправки.

Размер проверяется до скачивания, если известен, и контролируется во время загрузки. Длительность проверяется по доступным метаданным, затем подтверждается FFprobe. Превышение предела завершает задание понятной ошибкой.

### Разбиение

- Целевая длительность части — **10 минут**.
- В последние 8 секунд перед границей ищется пауза длительностью от 0,3 секунды.
- При отсутствии подходящей паузы используется граница по времени.
- Части идут последовательно, без перекрытия и пропусков.
- Подготовленный звук: WAV PCM16, 16 кГц, моно.
- Каждый отправляемый файл дополнительно проверяется на размер; исходное значение лимита загрузки — 25 МБ.
- Короткий файл поддерживаемого Groq формата, укладывающийся в ограничения, можно отправить без преобразования.

Ответ каждой успешной части атомарно сохраняется в контрольную точку. После сбоя уже сохранённые части повторно не распознаются.

Groq поддерживает `verbose_json` и временные метки сегментов. Размер допустимой загрузки зависит также от способа отправки и тарифа; в v1 используются файловые вложения до 25 МБ. [Документация Groq](https://console.groq.com/docs/speech-to-text).

### Результаты

**TXT:**

- UTF-8.
- Полный текст без временных меток и обозначений частей.
- Между текстами частей добавляется пробел.
- Сохраняются формулировки и пунктуация распознавания, без дополнительного литературного редактирования.

**Verbose JSON:**

- При одном запросе сохраняется исходный объект ответа Groq.
- При нескольких запросах формируется объединённый объект с `text`, `duration`, `language`, `segments` и `chunks`.
- В `segments` времена отсчитываются от начала всей записи; идентификаторы сегментов перенумеровываются.
- Каждый элемент `chunks` содержит номер части, её границы и исходный ответ Groq с локальными временами.
- Общий `language` берётся из первой распознанной части; ответы остальных частей сохраняют собственные значения.
- Временные метки отдельных слов в v1 не запрашиваются.

Таким образом, JSON длинной записи является результатом сборки бота, а исходные ответы Groq доступны внутри него.

В чат отправляется до 3000 символов текста. Более длинный текст обрезается для превью с отметкой, что полная версия находится в TXT. Оба файла отправляются всегда, включая короткие записи. Имена файлов очищаются от недопустимых символов и содержат ID задания.

Если итоговый текст пуст, бот сообщает, что речь не распознана, и отправляет пустой TXT вместе с JSON.

## 4. Надёжность, хранение и безопасность

### Очередь и восстановление

В базе сохраняются этап, прогресс, время следующей попытки и сведения о доставленных результатах.

- Повторно доставленный Telegram update не создаёт второе задание.
- После перезапуска обработчик продолжает незавершённый этап.
- Временные сетевые ошибки и ошибки сервера повторяются ограниченно.
- Исчерпание квоты переводит задание в ожидание с автоматическим продолжением.
- Ожидание не реализуется бесконечными запросами к Groq.
- Ошибка отправки результата не запускает повторное распознавание.
- TXT и JSON имеют отдельные отметки успешной доставки.

Для Free опубликованы ограничения **7200 секунд аудио в час и 28 800 секунд в сутки**. Поэтому четырёхчасовая запись может потребовать ожидания. Настройки аккаунта и ответы API имеют приоритет над опубликованными значениями. [Лимиты Groq](https://console.groq.com/docs/rate-limits).

После окончательной ошибки задание освобождает очередь и получает кнопку продолжения. Ручное продолжение ставит его в конец очереди, сохраняя готовые части.

Отмена прекращает дальнейшую обработку. Уже выполняющийся запрос Groq может завершиться; его результат не выдаётся после отмены.

После неопределённого исхода сетевого запроса возможна повторная обработка одной части. Аналогично, после потери ответа Telegram возможна повторная доставка файла. Гарантия однократного выполнения внешних запросов не заявляется.

### Хранение

| Состояние | Политика |
|---|---|
| Выполняется или ожидает квоту | Хранить необходимый исходник и контрольные точки |
| Успешно отправлены оба файла | Удалить исходник, временное аудио, ответы частей, TXT и JSON |
| Окончательная ошибка | Хранить необходимые файлы 7 дней для продолжения |
| Отмена | Удалить файлы после остановки активных операций |
| История задания | Хранить бессрочно в SQLite |

История содержит ID задания, пользователя и чат, тип источника, исходную ссылку либо Telegram file ID, название, размер, длительность, даты, модель, итоговый статус и код ошибки. Текст расшифровки и ответы Groq в бессрочную историю не входят.

Очистка охватывает также скачанные файлы в локальном кеше Telegram Bot API. Удаляются только учтённые медиафайлы внутри разрешённого каталога, когда они больше не используются заданиями; служебная база Bot API сохраняется. Повторное скачивание после очистки проверяется интеграционным тестом.

Уже отправленные сообщения и файлы в Telegram не удаляются.

### Загрузчик Mail.ru

Используется собственный модуль HTTPX. `mailru-cloud-guest-api` исключается из зависимостей: в просмотренном коде обнаружены неправильный разбор вложенных путей и отсутствие необходимых ограничений скачивания. Проверка опубликованных исходников не является гарантией безопасности будущих версий. [Проверенный исходник](https://github.com/aratakileo/mailru-cloud-guest-api/blob/main/mailru_cloud_guest_api/__init__.py).

Требования к загрузчикам:

- Проверять схему, адрес назначения, DNS и каждое перенаправление.
- Запрещать обращения по пользовательским ссылкам к локальным, частным и служебным сетям; соединение должно использовать проверенный адрес.
- Для Mail.ru разрешать HTTPS и серверы в доменах `cloud.mail.ru`, `datacloudmail.ru` и их поддоменах; неизвестный сервер отклонять. Домен `datacloudmail.ru` подтверждён пользователем для перенаправлений скачивания.
- Проверять TLS-сертификаты.
- Ограничивать размер ответа, скачивания, время ожидания и число перенаправлений.
- Сохранять файлы только в каталог конкретного задания.
- Не исполнять скачанный код, не распаковывать архивы.
- Запускать внешние программы без shell-интерполяции пользовательских данных.

Ключи хранятся вне Git и не попадают в логи. Полные исходные ссылки сохраняются в защищённой базе; токены, содержимое ответов и чувствительные параметры URL не записываются в технические журналы.

## 5. Настройки по умолчанию и критерии готовности

Дополнительные числовые настройки v1 фиксируются как изменяемые параметры:

- До 3 незавершённых заданий на пользователя и 30 на всю очередь.
- До 5 повторов временной ошибки с увеличением задержки.
- Для 429 использовать `Retry-After`; при его отсутствии увеличивать интервал проверки до часа.
- Обновлять сообщение о прогрессе не чаще одного раза в 5 секунд.
- Проверять очистку просроченных файлов раз в 10 минут и при запуске.
- При нехватке места отклонять новую загрузку, сохраняя возможность завершить и очистить существующие задания.

Развёртывание требует токена бота, ключа Groq, Telegram `api_id`/`api_hash` для собственного Bot API и списка разрешённых пользователей. Bot API доступен только внутри сети Compose. Настройки и секреты предоставляются при подготовке запуска.

Обязательные проверки:

1. Короткие аудио, видео, голосовое и видеокружок дают превью, TXT и JSON.
2. Telegram-вложение больше 20 МБ принимается через собственный Bot API.
3. Запись дольше 10 минут собирается без пропущенных интервалов; времена сегментов глобальные.
4. Проверяются границы в паузах, непрерывная речь и короткая последняя часть.
5. Перезапуск после нескольких частей продолжает обработку без повторной отправки сохранённых частей.
6. 429, сетевые сбои, ошибки Groq и ошибки доставки проходят согласованные сценарии восстановления.
7. Групповые команды, проверка инициатора, выдача в исходную тему и ограничения доступа работают.
8. Удаление после выдачи, отмены и истечения 7 дней охватывает все содержательные копии; метаданные остаются.
9. Проверяются опасные URL, перенаправления в частную сеть, подмена DNS, выход за каталог задания и превышение размера.
10. Выполняются живые проверки YouTube, прямой ссылки и **предоставленной ссылки Mail.ru с вложенным путём** на целевом сервере.
11. Проверяются запуск Compose, сохранность SQLite после перезапуска и восстановление базы из резервной копии.

Успешная загрузка предоставленного файла Mail.ru с вложенным путём и проверка безопасности собственного загрузчика — обязательные условия готовности первой версии.
