# TranscriptorBot

Telegram-бот для транскрипции аудио и видео через Groq с моделью
`whisper-large-v3-turbo`.

Планируемые источники: вложения Telegram, YouTube, публичные ссылки Облака
Mail.ru и прямые ссылки на медиафайлы. Результаты: превью текста, полный TXT
и verbose JSON.

## Документация

- [Спецификация v1](docs/specs/transcriptbot-v1.md)
- [Технический план реализации](docs/plans/transcriptbot-v1-implementation.md)

## Состояние проекта

Реализованы этапы 1–3: конфигурация, CLI, контейнеры, SQLite/WAL с миграциями,
очередь FIFO и Telegram-интерфейс. Бот принимает вложения и ссылки, поддерживает
команды, историю, статусы, отмену и продолжение. Приём update, ответ в outbox
и продвижение polling offset фиксируются атомарно. Отдельная корутина отправляет
статусы и готовые результаты, повторяя только неподтверждённые операции.

Worker защищён файловой блокировкой и читает сохранённый активный этап при запуске.
Загрузчики и медиа-конвейер относятся к этапам 4–5; сейчас worker ожидает остановки,
а принятые ботом задания остаются в очереди. Физическая очистка относится к этапу 6.

Согласованный стек: Python 3.12, aiogram 3, Groq SDK, FFmpeg/FFprobe,
yt-dlp, HTTPX, SQLite и Docker Compose.

## Настройки

Шаблон настроек находится в [.env.example](.env.example). Рабочие значения
и ключи хранятся в локальном `.env`, исключённом из Git. Параметры Telegram
и список разрешённых Telegram ID нужно заполнить перед запуском.

`ALLOWED_USER_IDS` — положительные ID через запятую. Модель фиксирована
спецификацией. Приложение читает `.env` из текущего каталога; переменные
окружения имеют приоритет. Неверные настройки завершают процесс с кодом 2,
без вывода значений секретов.

## Локальная разработка и проверки

Нужны Python 3.12 и uv. Для worker также нужны FFmpeg, FFprobe и Deno
версии от 2.3.0. В контейнерном образе эти программы уже установлены.

```bash
uv sync --locked
uv run --locked pytest
uv run --locked ruff check .
uv run --locked ruff format --check .
```

Пути в шаблоне рассчитаны на контейнеры. Для локальных проверок
можно переопределить пути, не изменяя секреты в `.env`:

```bash
mkdir -p var/data var/jobs var/telegram
SQLITE_PATH="$PWD/var/data/transcriptbot.sqlite3" \
WORK_DIR="$PWD/var/jobs" TELEGRAM_FILES_DIR="$PWD/var/telegram" \
uv run --locked transcriptbot migrate

SQLITE_PATH="$PWD/var/data/transcriptbot.sqlite3" \
WORK_DIR="$PWD/var/jobs" TELEGRAM_FILES_DIR="$PWD/var/telegram" \
uv run --locked transcriptbot bot --check
```

Без `--check` бот подключается к настроенному собственному Bot API,
запускает long polling и sender; worker пока ожидает SIGTERM или Ctrl+C.
При недоступности Bot API бот повторяет подключение. Неверный токен или конфликт
polling завершают процесс с безопасным сообщением, без вывода ответа API.
Для другого файла настроек доступен `--env-file /absolute/path/to/settings.env`.
Проверка `--check` не обращается к Telegram или Groq и не создаёт базу.
Перед запуском `bot` и `worker` нужно отдельно выполнить `transcriptbot migrate`.
Команда не требует FFmpeg/Deno и доступа к Telegram-кешу, повторный запуск безопасен.
Процессы отказываются запускаться с отсутствующей, устаревшей или несовместимой схемой;
миграции автоматически при старте не выполняются.

SQLite использует отдельный поток доступа в каждом процессе, WAL, foreign keys,
busy timeout 10 секунд и `synchronous=FULL`. Приём update, проверка лимитов и
назначение номера очереди фиксируются одной транзакцией. Ожидание текущего задания
удерживает очередь; продолжение после ошибки ставит прежний ID в конец,
сохраняя этап, части и подтверждения доставки. История доступна владельцу;
групповое чтение дополнительно ограничено чатом.

Изменение состояния проверяет его версию, а кнопки — поколение задания после
продолжения. Отмена не перезаписывается поздним ответом; старые кнопки не управляют
новой попыткой. В SQLite сохраняются только метаданные и ссылки на файлы.

## Telegram-интерфейс и доставка

В личке отправьте вложение или одну ссылку. В группе используйте
`/transcribe <ссылка>` или `/transcribe` ответом на файл/ссылку;
форма `/transcribe@BotName` поддерживается. Доступ проверяется по инициатору.
`/start`, `/help`, `/jobs` и `/status <id>` доступны тем же разрешённым пользователям.
История в группе ограничена владельцем и этой группой; в личке видна вся собственная история.
Кнопки «Отменить» и «Продолжить» также доступны в ответе `/status`.

Статус изменяется в одном сообщении не чаще заданного интервала (минимум 5 секунд).
Если сообщение удалено, создаётся замена. Команды и результаты сохраняют исходную
тему обсуждения. Отправки одного чата ограничиваются: минимум 1 секунда в личке,
3 секунды в группе; Telegram `Retry-After` сохраняется и переживает перезапуск.

Превью читается из TXT перед отправкой и не хранится в SQLite. TXT и JSON получают
отдельные подтверждения доставки. После ошибки отправки продолжение сохраняет
этап `deliver` и уже отправленные файлы. Неопределённый исход внешнего запроса может
привести к повторной доставке; гарантия однократной отправки не заявляется.

Для подключения будущего worker: после публикации результатов и перехода в `deliver`
вызвать `TelegramStore.enqueue_results(expected_job, txt=..., verbose_json=...)`.
Артефакты должны находиться в `WORK_DIR/<job_id>/`. Бот проверяет состояние перед
отправкой и отмечает завершение после подтверждения превью и обоих файлов;
`cleanup_pending` передаёт очистку будущему worker. Реальное распознавание ещё не выполняется.

## Контейнерное окружение

```bash
docker compose config --quiet
docker compose build
python3 scripts/check_containers.py
```

Последняя команда запускает временные контейнеры с вымышленными ключами,
без сети, проверяет миграции, обе команды, блокировку второго worker,
целостность базы на общих томах и SIGTERM. Дополнительно на подставном API
проверяются Telegram-приём, повторы update, offset, статус и восстановление
частично доставленного результата. После проверки удаляются только
созданные ею контейнеры и тома. Рабочие сервисы при этом не запускаются.

После сборки перед запуском сервисов примените миграции на томе `data`:

```bash
docker compose run --rm --no-deps worker migrate
```

Эта отдельная команда использует тот же образ и пользователя, что и worker;
дополнительный постоянный сервис в Compose не добавляется.

Compose описывает три сервиса: бот, один worker и официальный Telegram Bot API
в режиме `--local`. Сервер собирается из
[официальных исходников](https://github.com/tdlib/telegram-bot-api)
на commit `e3e9dd8e5b3d7ab8537cd5a10dc31d5ffa8f82d1` с закреплённым TDLib.
Образы Python, uv и Deno закреплены digest; системные пакеты берутся из
снимка Debian от 2026-10-01. Python-пакеты и их хеши находятся в `uv.lock`.

Все сервисы используют UID/GID `10001:10001`. Bot API не публикует порты
на хост. Постоянные тома `data`, `work` и `telegram` хранят SQLite,
рабочие файлы и кеш/служебные данные сервера. Бот получает том `telegram`
только для чтения, worker — также для будущей очистки учтённых файлов.
Не удаляйте эти тома командой `docker compose down -v` на рабочем экземпляре.

В общем образе приложения доступны FFmpeg/FFprobe, yt-dlp и Deno 2.9.7.
Установлен `yt-dlp[default]` с локальным EJS, согласно
[инструкции yt-dlp](https://github.com/yt-dlp/yt-dlp/wiki/EJS).
Обновления зависимостей во время работы не выполняются.
Инструкция полноценного первого запуска появится после реализации
конвейера; развёртывание согласовывается отдельно.
